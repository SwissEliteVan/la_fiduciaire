# Contrat des agents — règles de niveau supérieur du kit

**À utiliser comme référence lors de l'installation ; ne jamais remplacer un `AGENTS.md` existant sans revue du diff et autorisation.**

1. Répondre en français, communiquer faits, hypothèses et tests distinctement.
2. Exécuter les changements minimaux autorisés ; ne pas enchaîner vers une autre fonctionnalité qui contourne une autorisation manquante.
3. **Kit universel :** aucun assistant IA, fournisseur, hébergeur, framework ou langage n'est imposé par le kit. **Exception non négociable : vidéo hero réelle sur chaque accueil web**, quel que soit le profil ou le PRD. Ce sont les règles existantes du projet, ses ADR et les décisions du propriétaire qui s'appliquent. Le travail reste possible sans IA, avec une seule IA ou avec deux.
4. **Profil facultatif `strict-local-web` :** il s'applique uniquement si `projet/PROFIL.md` contient `profil: strict-local-web` (activé sur demande du propriétaire). Dans ce cas seulement, appliquer [`profils/STRICT-LOCAL-WEB.md`](profils/STRICT-LOCAL-WEB.md) (Hostinger Business/Infomaniak, données locales, services tiers exclus, multilingue ; la vidéo hero est obligatoire même hors profil strict).
5. La stack est choisie selon le PRD et les capacités **vérifiées** de l'environnement d'exécution retenu, avec ADR et alternatives ; pas de migration de stack implicite pour projet existant.
6. Aucun média ni composant sans origine/licence vérifiée ; accessibilité et langues selon le PRD du projet, **vidéo hero obligatoire pour chaque accueil web indépendamment du PRD**.
7. Décisions sensibles : déploiement, changements serveur/DNS, secrets, droits, suppression de données, migration destructive, dépenses, publication d'actifs douteux → **accord spécifique explicite**.
8. Git — **politique impérative du propriétaire pour le kit et tout projet piloté : travailler exclusivement sur la branche existante `main`, dans le répertoire courant du dépôt**. Interdiction de créer ou utiliser une branche secondaire, un `git worktree` (même sur `main`) ou une pull request. Avant toute écriture, vérifier la racine Git, `git branch --show-current` (= `main`) et `git status -sb`. Si la branche courante n'est pas `main` ou si `main` est absente : **STOP**, signaler la situation au propriétaire, ne pas créer ni changer de branche automatiquement. Aucun commit/push sans autorisation explicite ; jamais de force-push, rebase destructeur, `reset --hard`, nettoyage destructeur ni écrasement de travail non commité.
9. Coordination : appliquer [`coordination/PROTOCOLE-2-IA.md`](coordination/PROTOCOLE-2-IA.md). L'autre IA n'est pas automatiquement activée par un commentaire.
10. Secret : ne jamais exposer token, e-mail privé, dossier client ou clé dans commits, issues, rapports ou journaux ; vérifier côté serveur tous les accès et données.
11. Un seul travail actif documenté, pas de second backlog. Avec deux IA choisies : l'auteur (IA A) construit et la relectrice (IA B) audite, rôles attribués par tâche ; un agent ne modifie pas le périmètre CLAIM de l'autre. Sans seconde IA, aucune relecture n'est inventée.
12. Vérifier avant `terminé` : code réellement lu, tests exécutés, erreurs et limites, sécurité, droits, restaurabilité et preuves, plus les critères applicables au projet (rendu mobile, i18n, poids médias…) ; suivre la [`Definition of Done`](projet/DEFINITION-OF-DONE.md).
13. Réduire l'usage de tokens : charger seulement les compétences nécessaires, résumer, citer fichiers/SHAs, éviter de recopier de longs historiques.
14. **Captures QA et économies de tokens — INTERDICTION PAR DÉFAUT :** ne créer aucun dossier de captures, tel que `medias/qa/refonte-apres`, aucune série de screenshots PNG/JPG, aucun `mesures.json` de QA, aucune navigation automatisée pour captures et aucune analyse d'images par IA sans autorisation spécifique, explicite et préalable du propriétaire pour une tâche bornée. Une URL de recette configurée n'est pas une autorisation. Préférer lint, tests ciblés sans navigateur et preuves textuelles ; signaler `NON EXÉCUTÉ` lorsque la recette visuelle n'est pas autorisée. Ne supprimer aucun fichier déjà présent. Les médias du produit explicitement demandés restent autorisés.
15. **RÈGLE NON NÉGOCIABLE — VIDÉO HERO OBLIGATOIRE, SANS CONDITION DE PROFIL OU DE PRD : pour tout projet piloté par le kit possédant une page d'accueil web (site, vitrine, application avec accueil), inclure une vraie vidéo locale dans le hero, avec poster local, fallback, pause accessible, mobile et prefers-reduced-motion. Cela vaut pour NOUVEAU et EXISTANT, y compris hors strict-local-web. Image fixe seule, CSS animé, vidéo distante ou simple balise sans source réelle ne satisfont pas l'exigence. Si la vidéo source ou sa licence manque, statut BLOCKED_MEDIA ; pas de DONE, d'approbation finale ou de publication sans décision explicite du propriétaire. Ne générer, télécharger, transcoder ou analyser aucune vidéo sans autorisation spécifique ; préserver les médias existants. Pour un projet purement CLI/backend sans accueil web, consigner la contrainte pour l'éventuelle future interface, sans créer un frontend non demandé.**
